### Порядок проверки условий и достижимость ветвей

Все четыре ветви классификации по баллу достижимы: для каждой существует непересекающийся диапазон входных значений. Ветви `exam`, `project`, `practice` и `case _` также достижимы. Для некорректных входных данных последующие этапы намеренно не выполняются из-за раннего возврата. Условие дальнейшего снижения уровня ложно для уже «недостаточного» результата, что сохраняет нижнюю границу категории.

## Задание 2. Циклы и базовые алгоритмические схемы

### Оценка сложности

| Алгоритм | Временная сложность | Дополнительная память | Обоснование |
|---|---|---|---|
| Подсчет статистики | `O(n)` | `O(1)` | Два последовательных прохода по списку |
| Линейный поиск | `O(n)` | `O(1)` | В худшем случае проверяются все элементы |
| Проверка простоты | `O(√n)` | `O(1)` | Проверяются делители до квадратного корня |
| Сортировка выбором | `O(n²)` | `O(n)` в реализации | Алгоритм использует `O(1)` служебной памяти, но функция копирует входной список, чтобы не изменять его |
| Бинарный поиск | `O(log n)` | `O(1)` | На каждой итерации диапазон поиска уменьшается примерно вдвое |

### Пояснение параметров сложности алгоритмов

- Подсчет статистики. Пусть n — количество элементов списка measurements. Первый проход выполняет n итераций, второй — еще n итераций; суммарно около 2n операций, поэтому временная сложность O(n). Дополнительная память O(1): используются только счетчики, сумма, среднее, минимум и максимум; новый список не создается.
- Линейный поиск. Число операций зависит от n — длины просматриваемого списка. В лучшем случае найденный элемент стоит первым (O(1)), в худшем случае проверяются все n элементов или элемент отсутствует (O(n)). Дополнительная память O(1), так как хранятся только индекс и искомое значение.
- Проверка простоты. Здесь n — проверяемое целое число, а не длина списка. Проверяются возможные делители до √n, поэтому число проверок пропорционально √n и временная сложность равна O(√n). Дополнительная память O(1): используется несколько переменных для числа и текущего делителя.
- Сортировка выбором. Пусть n — количество элементов сортируемого списка. Для каждого элемента ищется минимум в оставшейся неотсортированной части; суммарное число сравнений равно (n−1)+(n−2)+…+1 = n(n−1)/2, поэтому временная сложность O(n²). Сам алгоритм требует O(1) служебной памяти, но представленная реализация создает копию входного списка, поэтому дополнительная память всей функции — O(n).
- Бинарный поиск. Параметр n — количество элементов уже отсортированного списка. На каждой итерации область поиска уменьшается примерно вдвое, поэтому число итераций и временная сложность составляют O(log n). Дополнительная память O(1): используются left, right, middle и счетчик сравнений; рекурсия и дополнительные коллекции не применяются.
- Почему достаточно проверять делители до квадратного корня. Если n — составное число, то n = a·b для целых множителей больше единицы. Если бы оба множителя были больше √n, то их произведение было бы больше n, что невозможно. Следовательно, хотя бы один множитель не превосходит √n. Поэтому при отсутствии делителей от 2 до floor(√n) включительно число простое; проверять большие делители отдельно не требуется.

## Задание 3. Коллекции и выбор структуры данных

### Объяснение
- Множество подходит для хранения уникальных значений так как множество (set) автоматически удаляет дубликаты. Каждый элемент хранится только один раз. Добавление и проверка наличия элемента в среднем выполняются за O(1).
- Кортеж (tuple) можно использовать как ключ словаря так как является неизменяемым и хешируемым, если все его элементы хешируемы. Поэтому его можно использовать в качестве ключа словаря, например ("anna", "lab_01").
- Список (list) является изменяемым и нехешируемым типом данных. Поэтому Python не позволяет использовать его в качестве ключа словаря.
- Словарь позволяет искать результат по составному ключу, например (student, laboratory), в среднем за O(1). В списке для поиска пришлось бы последовательно проверять элементы, что занимает O(n).


**Сложность:** построение структур по `N` записям занимает в среднем `O(N)` времени. Добавление одной новой записи — `O(1)` в среднем для множеств и словарей и амортизированно `O(1)` для добавления в список попыток. Поиск по составному ключу словаря — `O(1)` в среднем.

## Задание 4. Функции, параметры и области видимости

### Области видимости LEGB

```text
Global (модуль)
└── course = "Python"
    └── Enclosing (outer_function)
        └── course = "Algorithms"
            └── Local (inner_function)
                └── nonlocal course изменяет переменную Enclosing
```

Порядок поиска имен в Python:

1. **L — Local:** локальная область текущей функции.
2. **E — Enclosing:** область объемлющей функции.
3. **G — Global:** пространство имен модуля.
4. **B — Built-in:** встроенные имена Python.

Во вложенной функции `nonlocal course` указывает на переменную `course` из `outer_function`. После вызова вложенной функции значение в объемлющей области становится `"Databases"`, а глобальная переменная остается `"Python"`.

### Изменяемое значение по умолчанию

1. Объясните ошибку через жизненный цикл объекта значения по умолчанию.

Ответ: В функции add_result(value, results=[]) список создаётся один раз — при определении функции, а не при каждом её вызове. При последующих вызовах без аргумента results используется тот же самый список. Метод append() изменяет его, поэтому значения накапливаются между вызовами: [1], [1, 2], [1, 2, 3].

Исправление: использовать None в качестве значения по умолчанию и создавать новый список внутри функции при каждом вызове.

2. Объясните, какое значение сохраняется в замыкании.

Ответ: В замыкании сохраняется значение переменной threshold, переданное при создании функции checker. Поэтому checker_80 сохраняет порог 80, а checker_90 — порог 90. Каждая функция использует своё сохранённое значение независимо от другой.

**Сложность:** `arithmetic_mean` и `build_report` — `O(n)` времени и `O(1)` дополнительной памяти для вычисления среднего; `normalize_name` — `O(c)` времени и памяти, где `c` — длина строки; `collect_tags` — `O(t)` в среднем и `O(u)` памяти, где `t` — число входных тегов, `u` — число уникальных тегов; `apply_to_results` — `O(n)` времени и `O(n)` памяти для результирующего списка.

## Задание 5. Анализатор учебных результатов

### Декомпозиция и сложность

Программа разделена на функции с одной основной ответственностью: вычисление среднего, минимума и максимума; классификация; формирование сводки студента; агрегация группы; поиск лидеров; построение рейтинга; форматирование отчета. Такое разделение позволяет проверять функции независимо, повторно использовать статистические операции и изменять правила классификации без переписывания форматирования.

Пусть `S` — число студентов, `R` — общее число результатов. Вычисление сводок, среднего группы, категорий и лидеров требует `O(R + S)` времени. Построение рейтинга методом вставок требует `O(S²)` в худшем случае. Поэтому общая временная сложность `group_summary` — `O(R + S²)`, дополнительная память — `O(S)` для сводок и рейтинга. Форматирование отчета занимает `O(S)` времени без учета длины числовых строк.
