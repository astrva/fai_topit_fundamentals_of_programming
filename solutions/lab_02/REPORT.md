## Задание 2.

### Таблица наблюдений:
| Операция | Новый внешний объект | Новые вложенные объекты | Изменения независимы |
|---|----------------------|-------------------------|----------------------|
| Присваивание | нет                  | нет                     | нет                  |
| Поверхностная копия | да                   | нет                     | частично             |
| Глубокая копия | да                   | да                       | да                   |

**Объяснение:** В выражении [[0] * 3] * 3 внутренний список создаётся один раз, а внешний * 3 просто раскладывает три ссылки на него. Поэтому wrong_matrix[0] is wrong_matrix[1] даёт True — все строки это один объект, и изменение в одной строке меняет все. В выражении [[0] * 3 for _ in range(3)] генератор создаёт новый список на каждой итерации. Поэтому correct_matrix[0] is correct_matrix[1] даёт False — строки это разные объекты, и изменение в одной строке не затрагивает остальные.

**Вопросы для анализа:**
1. Поверхностная копирует только верхний уровень контейнера, вкладывая ссылки на исходные вложенные объекты. Глубокая рекурсивно копирует все уровни.
2. Глубокое копирование ресурсоемко (время и память), может вызвать бесконечную рекурсию при циклических ссылках, и не копирует некоторые объекты.
3. Поверхностной копии достаточно когда контейнер содержит только неизменяемые объекты или когда намеренно нужно сохранить общие ссылки на вложенные изменяемые объекты.

## Задание 3.

**Объяснение:**
- Функция sys.getrefcount() получает объект как аргумент, что создает временную дополнительную ссылку на время выполнения функции.
- Увеличивают счетчик: присваивание имени (alias = data), добавление в контейнер (container = [data]).
- Уменьшают счетчик: удаление имени (del alias), удаление из контейнера (container.clear()).
- del удаляет привязку имени в текущем пространстве имен. Объект удаляется сборщиком мусора только тогда, когда его счетчик ссылок достигает нуля.

**Объяснение:** Слабая ссылка (weakref.ref) не увеличивает счетчик ссылок объекта. Поэтому, когда удаляются все сильные ссылки (del record), счетчик падает до 0, объект уничтожается, и слабая ссылка начинает возвращать None.

**Пример:** Кэширование тяжелых объектов. Словарь кэша может хранить слабые ссылки на объекты. Если они больше не нужны основной программе, они автоматически удалятся из памяти и из кэша, предотвращая утечки памяти.

**Вопросы для анализа:**
1. Подсчет ссылок позволяет освободить объект когда счетчик ссылок на объект становится равным нулю.
2. Нет. CPython часто возвращает память в свой собственный аллокатор для повторного использования, а не сразу операционной системе.
3. Сильная ссылка увеличивает счетчик ссылок и предотвращает удаление объекта. Слабая ссылка позволяет получить доступ к объекту, если он жив, но не мешает его удалению.

## Задание 4.

**Объяснение:**
- Подсчёта ссылок недостаточно потому что в цикле каждый список удерживается другим, поэтому после del first и del second счётчики равны 1, а не 0. Подсчёт ссылок такие объекты не удалит. Циклический сборщик находит группу целиком и освобождает её.
- Поколения нужны потому что новые объекты проверяются часто, пережившие сборку — реже. Это экономит время, не нужно постоянно обходить всю память.

**Схема графа:**
```text
node1 ──► node2 ──► node3
  ▲                   │
  └───────────────────┘

node4 — отдельно, ссылок нет
```

**Вопросы для анализа:**
1. Цикл возникает, когда A ссылается на B, а B обратно на A.
2. Объект с ненулевым счётчиком может быть недостижим из-за циклических ссылок внутри изолированной группы, на которую нет ссылок извне программы.
3. Сборщик мусора разделяет отслеживаемые объекты по поколениям чтобы реже проверять старые объекты и не тратить время на всю память.

## Итоговый анализ

1. **Не создавать все элементы сразу, а вычислять их по мере необходимости.** В части 3 задания 5 range(100_000) занял доли килобайта, а list(range(100_000)) — сотни килобайт. Для больших данных, где не нужен одновременный доступ ко всем элементам, выгоднее использовать range, генераторы или итераторы.

2. **Избегать скрытых общих ссылок при создании вложенных структур.** В задании 2 [[0]*3]*3 создал три ссылки на один список, а [[0]*3 for _ in range(3)] — три независимых объекта. При работе с матрицами и таблицами нужно использовать генераторы, чтобы не заполнять память случайными копиями или, наоборот, не получать общее состояние там, где нужна независимость.

3. **Применять слабые ссылки для кэшей и реестров.** В задании 3 WeakValueDictionary автоматически удалял объекты, когда на них не оставалось сильных ссылок. Для кэшей тяжёлых объектов это предотвращает утечки памяти: объект живёт только пока нужен основной программе.
