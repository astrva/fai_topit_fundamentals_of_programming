## Задание 2.

### Прогноз сравнений:
- `a == b`: True
- `a is b`: True
- `a == c`: True
- `a is c`: False

### Схема связей имен и объектов

```
a ──┐
    ├──> int(1000)   # один и тот же объект
b ──┘

c ───> int(1000)    # другой объект, полученный через int("1000")
```
**Разница между == и is:** Оператор == проверяет равенство значений, а  is сравнивает id объектов.

**Проверка на None:** `c is None`.

**Эксперимент со строками:** first == second вернет True. first is second также может вернуть True из-за интернирования строк на этапе компиляции.

**Правило:** == для сравнения значений чисел, строк, списков и т.п., is проверяет, указывают ли имена на один и тот же объект в памяти.

**Контрольные вопросы:**
1. Нет, конструкция b = a создает новую ссылку на тот же объект.
2. type() возвращает тип объекта, а id() возвращает идентификатор объекта, обычно его адрес в памяти.
3. None всегда один в памяти, а числа/строки могут быть разными объектами с одинаковым значением.

## Задание 3.

- **Эксперимент A:** оператор / выполняет истинное деление и всегда возвращает float, даже если числа делятся нацело, а оператор // выполняет целочисленное деление и всегда возвращает int и округляет результат всегда в меньшую сторону.
- **Эксперимент B:** Python поддерживает целые числа произвольной точности. В отличие от C++ или Java, где int имеет фиксированный размер (например, 32 бита) и может переполниться, в Python память под число выделяется динамически, поэтому 2 ** 1000 вычислится корректно без ошибки переполнения.
- **Эксперимент C:** 0.1 + 0.2 == 0.3 вернет False. Это происходит из-за того, что дробные числа хранятся в памяти в двоичном формате (стандарт IEEE 754), и дроби вроде 0.1 не могут быть представлены точно, возникающая микроскопическая погрешность (result - 0.3 даст число порядка 5.55e-17).
Правило безопасного сравнения: Всегда использовать math.isclose(a, b) для чисел с плавающей точкой.
- **Эксперимент D:**  bool("False") возвращает True, потому что в Python любое непустое строковое значение считается истинным. Ложными являются только пустая строка "", число 0, 0.0, None. Комплексное число (2-3j) имеет действительную часть 2.0 и мнимую -3.0.

**Контрольные вопросы:**
1. Результат обычного деления двух объектов int имеет тип float для того, чтобы сохранить возможную дробную часть результата.
2. Первое разбирает строку и делает целое число. Второе отбрасывает дробную часть у float числа, результат будет 42.
3. Falsy значения из опыта: 0, "".

## Задание 4.

**Неизменяемость строк:**
Попытка сделать symbol[0] = 'a' вызовет ошибку TypeError: 'str' object does not support item assignment.
Причина: Строки в Python являются неизменяемыми объектами. Нельзя изменить символ по индексу у существующей строки.

**Контрольные вопросы:**
1. len() считает символы, а .encode("utf-8") считает байты. Кириллица в UTF-8 занимает 2 байта.
2. Границы и шаг в text[start:stop:step] означают: start — индекс начала (включительно), stop — индекс конца (не включительно), step — шаг выборки (по умолчанию 1).
3. Методы вроде .upper() не меняют исходную строку, а создают и возвращают новую.

## Вывод: 3 неожиданные особенности Python

1. Разница идентичсности и равенства: a == b и a is b — принципиально разные проверки, и совпадение id не доказывает равенство значений (кеширование, интернирование детали реализации).

2. Целые произвольной точности и погрешность float. Python спокойно считает 2 ** 1000, но 0.1 + 0.2 != 0.3 — потому что int бесконечно точны, а float подчиняются IEEE 754.

3. Неизменяемость строк и Unicode. Строка — неизменяемый объект, а длина зависит от того, что считать: символы или байты кодировки.
